# Задание 1: Умножение матрицы на вектор

## Описание

Реализована многопоточная версия программы умножения матрицы на вектор с параллельной инициализацией массивов.

## Файлы

- `task1.cpp` - Исходный код программы
- `task1` - Скомпилированный исполняемый файл
- `task1_output.txt` - Результаты выполнения

## Сборка

```bash
g++ -std=c++20 -O2 -pthread -o task1 task1.cpp
```

## Запуск

```bash
./task1
```

## Реализация

### Подходы к параллелизации

1. **std::thread** - прямое создание потоков для обработки строк матрицы
2. **std::async** - асинхронное выполнение задач

### Параллельная инициализация

Массивы инициализируются параллельно с использованием `std::thread`. Количество потоков определяется через `std::thread::hardware_concurrency()`.

### Оптимизации

- Матрица хранится в виде плоского массива (`std::vector<double>`) для лучшей локальности данных
- Каждая строка матрицы обрабатывается одним потоком
- Равномерное распределение строк между потоками

## Результаты

Тестирование проводилось на размерах матриц 2000x2000 и 4000x4000 (ограничение по памяти сервера).

### Наблюдения

1. **Масштабируемость**: При увеличении количества потоков наблюдается ускорение вычислений, но только до определенного предела
2. **Оптимальное количество потоков**: 4 потока показывают наилучший результат (ускорение ~4x)
3. **Переподписка потоков**: При количестве потоков больше числа физических ядер производительность снижается из-за переключения контекста
4. **std::async vs std::thread**: Оба подхода показывают схожие результаты, std::async может быть немного эффективнее за счет лучшего планирования

## Вывод о масштабируемости

1. **Линейное ускорение** наблюдается только при количестве потоков ≤ числу физических ядер
2. **Закон Амдала**: Часть кода остается последовательной (синхронизация, создание потоков), что ограничивает максимальное ускорение
3. **Накладные расходы**: При малом размере задачи накладные расходы на создание потоков могут превысить выгоду от параллелизма
4. **Рекомендация**: Использовать количество потоков, равное числу физических ядер процессора

## Примечание

В задании указаны размеры матриц 20000x20000 и 40000x40000, но на тестовом сервере недостаточно памяти для таких размеров (~3.2GB и ~12.8GB соответственно). Поэтому использованы меньшие размеры для демонстрации принципов параллелизации.
