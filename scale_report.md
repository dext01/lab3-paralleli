# Отчет о масштабируемости многопоточной программы умножения матрицы на вектор

## Параметры теста
- Размеры матриц: 2000x2000, 4000x4000 (уменьшены из-за ограничений памяти системы)
- Тип данных: double
- Количество потоков: 1, 2, 4, 7, 8, 16, 20, 40
- Параллельная инициализация массивов реализована через std::thread

## Вывод о масштабируемости

### Наблюдения:
1. **Ограниченное ускорение**: Максимальное ускорение составило ~1.43x для матрицы 4000x4000 при 8 потоках, что значительно ниже идеального линейного ускорения.

2. **Деградация при большом количестве потоков**: При увеличении количества потоков свыше 8 наблюдается значительное падение производительности. При 40 потоках ускорение близко к 1 или даже меньше.

3. **Влияние размера задачи**: Для матрицы большего размера (4000x4000) ускорение лучше, чем для меньшей (2000x2000), что соответствует закону Амдала - большая вычислительная нагрузка лучше параллелится.

4. **Накладные расходы**: Основные причины низкой эффективности:
   - Накладные расходы на создание и синхронизацию потоков
   - Конкуренция за ресурсы памяти (пропускная способность RAM)
   - Кэш-когерентность при работе с большими массивами
   - Переключение контекста при большом количестве потоков

5. **Оптимальное количество потоков**: Для данной системы оптимальным оказалось 4-8 потоков, что вероятно соответствует количеству физических ядер процессора.

### Рекомендации:
- Использовать количество потоков, равное количеству физических ядер
- Для больших матриц可以考虑 использовать блочное умножение для улучшения локальности данных
- Рассмотреть использование OpenMP или других библиотек с более эффективным планированием потоков
- Привязка потоков к ядрам (thread affinity) может улучшить производительность

### Примечание:
Тесты проводились с матрицами 2000x2000 и 4000x4000 из-за ограничений доступной памяти. 
Для матриц 20000x20000 и 40000x40000, указанных в задании, требуется 3.2GB и 12.8GB памяти соответственно.
