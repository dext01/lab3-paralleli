# Задание 2: Клиент-серверное приложение

## Описание

Реализовано клиент-серверное приложение, где:
- **Сервер** - отдельный поток, который берет задачи из очереди, решает их и сохраняет результат
- **Клиенты** - три отдельных потока, каждый добавляет задачи своего типа

## Структура проекта

```
/workspace/
├── task_server.hpp      # Шаблон класса TaskServer<T>
├── main.cpp             # Основная программа с клиентами
├── test_results.cpp     # Тест для проверки результатов
├── CMakeLists.txt       # Файл сборки
└── README.md            # Этот файл
```

## Сборка

```bash
mkdir build && cd build
cmake ..
make
```

## Запуск

```bash
./bin/g++/task_server   # Запуск сервера и клиентов
./bin/g++/test_results  # Запуск тестов
```

## Интерфейс TaskServer

```cpp
template<typename T>
class TaskServer {
public:
    void start();                              // Запустить сервер
    void stop();                               // Остановить сервер
    size_t add_task(std::packaged_task<T()>);  // Добавить задачу, вернуть id
    T request_result(size_t task_id);          // Получить результат (блокирующий)
};
```

## Типы задач

1. **Клиент 1**: Вычисление синуса (arg ∈ [-100, 100])
2. **Клиент 2**: Вычисление квадратного корня (arg ∈ [0, 1000])
3. **Клиент 3**: Возведение в степень (base ∈ [1, 10], exp ∈ [0, 5])

## Синхронизация

Для синхронизации доступа к общим ресурсам используются:
- `std::mutex` - для защиты очереди задач и контейнера результатов
- `std::condition_variable` - для эффективного ожидания новых задач
- `std::shared_future` - для возможности многократного доступа к результату

## Выбор контейнера

Для хранения результатов выбран `std::unordered_map`, так как он обеспечивает:
- O(1) среднее время добавления элемента
- O(1) среднее время поиска элемента
- O(1) среднее время удаления элемента

Это оптимальный выбор для сценария, где требуется быстрый поиск по ID задачи.

## Выводы

1. **std::promise/std::future** идеально подходят для передачи результатов между потоками
2. **std::shared_future** позволяет нескольким потокам получать один результат
3. **std::condition_variable** эффективнее polling (активного ожидания) для уведомления о новых задачах
4. **std::unordered_map** обеспечивает быстрый доступ к результатам по ID задачи
